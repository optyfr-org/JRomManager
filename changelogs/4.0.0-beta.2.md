### Changed
- Native installer FILE names now embed `native` plus OS/arch (e.g. `JRomManager-Servers-native-win-x64-4.0.0.msi`, `jrommanager-native-servers-linux-x64`), so native artifacts no longer collide with the JVM installers or across architectures; installed folders and launchers keep their short names (`JRomManager-Servers`, `JRomManager`), each with its `.cfg`
- Native installers no longer ship the stock Java runtime or stub jar: the self-contained executables come with only their companion libraries plus client/scripts, making the MSI/DMG/DEB/RPM much smaller (macOS DMGs are built manually with `hdiutil` since jpackage signing requires the stock runtime layout)
- macOS-x64 CI skips GUI AOT training (it hangs on `CGLChoosePixelFormat` with no display); macOS-aarch64 still trains, with a warn-and-continue fallback for GUI launchers

### Fixed
- Packaged (JVM) startup with AOT cache: compressed oops is pinned and the heap capped at 8G, so the build-time trained cache maps on any machine (fixes the `Unable to use AOT cache` / `Unable to map shared spaces` fallback on large-RAM hosts)
- AOT training and launchers disable JVMCI (`-XX:-EnableJVMCI`), so the module graph matches on every JDK vendor (GraalVM defaults it on, Temurin off) and the cache keeps optimized module handling and AOT-linked classes instead of logging an addmods mismatch
- Native staging excludes `jrm*.sbom.json`, which broke macOS codesign inside `Contents/MacOS`
